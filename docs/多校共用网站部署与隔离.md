# 多校共用网站：隔离和首次使用

本方案让所有学校访问同一个静态网站，但**每所学校使用独立的 CloudBase 环境**。学校代号只负责在公开配置中选择环境；真正的学生名单、问卷、辅导员账号和数据库均在该校环境中。环境 ID 是公开标识，不是密码。不得把两所学校指向同一个环境；构建脚本会拒绝重复环境 ID。

这样选择是因为原试点的存储过程直接访问单校业务表；在同一数据库中仅增加网页筛选无法阻止跨校读取。[CloudBase 环境说明](https://docs.cloudbase.net/quick-start/env-overview)确认不同环境的数据库和身份认证相互隔离。以后学校数量很多时，需要重新评估逐校环境的维护工作量。

## 给新学校开通

1. 在云开发控制台为该校创建**新的 PostgreSQL 模式环境**，单独开启学生匿名登录和辅导员用户名密码登录。为该校创建辅导员账号，取得该账号 UID。现有试点环境不复用。
2. 在项目根目录的 `.env.local` 填写**这所新学校**的 `CLOUDBASE_ENV_ID` 和 `ADMIN_UID`，运行 `node scripts/apply-database.mjs`。该脚本会安装全部数据库文件，包括首次初始化及寝室容量校验。它只适合新环境的首次建库；旧脚本 `002_formal_rooms.sql` 会预置试点寝室，后续首次初始化事务会在确认环境中无学生及分寝记录后替换为本校寝室。**不要在正在使用的试点环境重复运行全套建库脚本。**
3. 在每个学校的云环境安全来源设置中添加**同一个网站域名**。本地联调时，还需加入实际本地地址和端口。[CloudBase SDK 初始化文档](https://docs.cloudbase.net/authentication-v2/method/sdk-init)说明 Web 页面来源未配置会发生跨域错误。
4. 给 `.env.local` 增加一行 `DORM_SCHOOLS_JSON`，列出所有已开通学校的名称、代号、环境 ID 与辅导员登录名。例子：

```dotenv
DORM_SCHOOLS_JSON={"school-a":{"name":"示例学校甲","envId":"env-a","adminUsername":"teacher-a"},"school-b":{"name":"示例学校乙","envId":"env-b","adminUsername":"teacher-b"}}
```

5. 运行 `npm run build`，在 `dist/shared/config.js` 核对每所学校代号对应不同环境 ID，再把同一份 `dist` 部署到一个网站域名。**这一步涉及真实外部服务和个人数据；本仓库目前没有替用户执行。**生产访问还要验证域名、安全来源、账号权限和 CloudBase 配额。CloudBase 当前文档对新环境默认域名有限制；正式网站宜使用合规自定义域名，详见[官方说明](https://docs.cloudbase.net/service/introduce)。

若要把原试点学校也列入同一个网站，先在测试环境验证升级，并备份试点环境；然后针对试点环境只运行 `node scripts/apply-safe-upgrades.mjs --dry-run` 查看目标，再运行 `node scripts/apply-safe-upgrades.mjs`。此脚本仅应用 `013`、`014`，不会重播旧文件中预置寝室的语句。试点环境已有学生，数据库仍会拒绝“首次初始化”；原有业务数据不应被重新导入。

## 辅导员首次使用

打开网站首页，先选自己的学校，再进入辅导员端。登录后如果本校云环境还没有学生数据，会进入「首次设置」。按模板先检查名单，再检查寝室；确认最后一步时，数据库函数 `dorm_admin_initialize` 会**一次性**核对并写入两份数据，床位不足会使整次事务回滚。后台以当前登录账号 UID 对照本校 `dorm_admins` 表；已有学生、问卷或分寝数据时拒绝重新初始化。需要后续补录或更正时，暂用经过审核的现有部署脚本或专门迁移，不能重复执行首次初始化。

学生从同一网站选择学校，班级列表只显示该校公开的班级名称；**班级填写码和学生名单不会由公开接口返回**。姓名、学号、班级、填写码仍由该校数据库核对。

单独为一个班级生成方案时，不使用跨班机动寝室；只有对全部班级一起生成时才考虑机动寝室。数据库的容量触发器还会阻止已有分配加上新分配超过寝室床位数。

## 上线前必须实测

- 至少建立两个真实测试环境，分别导入只含虚构数据的名单。甲校辅导员登录乙校入口必须失败；甲校学生在乙校不能通过身份核验。
- 未选学校和未知学校不能回退到试点环境。断网、错误环境 ID、数据库拒绝初始化时不得显示假数据或部分成功。
- 检查学校域名在每个云环境的安全来源配置、登录、公开班级接口、导入、问卷、组队、生成与发布完整流程。
- 用专门的测试新环境运行 SQL 迁移并实测拒绝重复初始化；当前仓库只有代码、静态检查与本地模拟验收，**没有真实 CloudBase 多环境验收证据**。

CloudBase 的 [RPC 文档](https://docs.cloudbase.net/database/postgresql/rpc)指出网关端可能不强制检查 `GRANT EXECUTE`。因此本项目的高权限初始化函数在函数体内核对 `auth.uid()` 和辅导员表，不能只靠前端隐藏按钮或 SQL 授权语句。
